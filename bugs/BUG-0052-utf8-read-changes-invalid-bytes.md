# BUG-0052 utf-8 として開くと、不正なバイトが別のバイトに変わり、前後の文字も巻き込まれることがある（保存でバイト列が変わる）

- 状態: 未修正（S4 の「生のバイトの文字」〈設計書 docs/refactoring/s4-char-design.md の 4a〉で直る見込み）
- 対象: x64 版（feature/x64-only）。x64 固有ではないと見られる
- 起票: 2026-11-22（BUG-0039 の判定の見直しの実測で見つけた）

## 症状
- ほとんど正しい utf-8 のファイルに不正なバイトが 1 つあると、判定は utf-8（utf8n）のまま（BUG-0039 の見直しで、判定が sjis に変わる退行は防いだ）だが、読んで保存するとバイト列が変わる。不正なバイトの後ろの 1 文字が巻き込まれることがある。
- sjis として開けばバイト列は保たれる。

## 実測（2026-11-22、`ed::find-file-internal`（符号は nil＝自動判定。判定は utf8n）で開き、`save-buffer` して、バイト列を読み戻した。`E3 81 82` は「あ」）
| 元のバイト列 | 保存後 |
|---|---|
| `E3 81 82 .. E3 81 FF 82 ..`（途中に FF） | `E3 81 BF ..`（FF 82 が BF 1 バイトになる） |
| `E3 81 A0 82 ..`（途中に A0） | `E3 81 A0 ..`（82 が消える） |
| `.. E3 81 82 0A FF`（末尾の FF） | FF が消える |
| `.. E3 81 82 0A E3 81`（末尾に途中で切れた文字） | `E3 81` が消える |

## 期待
- 不正なバイトは、そのバイトだけが元のバイトのまま保存で戻る。

## R4（2026-11-22）
- ファイルとソケットのストリーム・load は、1 の側で P1 の変換器に切り替え済み（src/stream.cc の stream_conv）。生のバイトの文字は元のバイトで書き戻る。0 の側の動き（バッファの読み書き）は変えていない。V で閉じる。
