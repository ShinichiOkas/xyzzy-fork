# BUG-0038 巨大な整数の指数の expt が、有理複素数の底では返らず、浮動小数の底で負の指数だと誤ったエラーになる

- 状態: 未修正
- 対象: x64 版（feature/x64-only）。x64 固有ではないと見られる
- 起票: 2026-11-22（BUG-0033 の残りの道の実測で見つけた）

## 症状
- 底が有理複素数で、指数が巨大な整数だと、返らない。
- 底が浮動小数（複素数を含む）で、指数が負の巨大な整数だと、結果が 0.0 に近いのに floating-point-overflow になる。結果が巨大なのに division-by-zero になるものもある。

## 実測（2026-11-22、20 秒の時間切れつき。1 式ごとに別の xyzzy）
| 式 | 結果 |
|---|---|
| `(expt #c(1 2) 4294967296)` | 20 秒で返らない |
| `(expt #c(1 2) (ash 1 70))` | 20 秒で返らない |
| `(expt #c(1 1) 4294967296)` | 20 秒で返らない |
| `(expt #c(3/5 4/5) 4294967296)` | 20 秒で返らない |
| `(expt #c(1/2 1/2) 4294967296)` | 20 秒で返らない |
| `(expt #c(1 2) -4294967296)` | 20 秒で返らない |
| `(expt 2.0 -4294967296)` | floating-point-overflow（結果は 0.0 のはず） |
| `(expt 2.0 -200)`（単精度） | floating-point-overflow（結果は 0.0 のはず） |
| `(expt #c(1.0 1.0) -4294967296)` | floating-point-overflow（結果は #C(0.0 0.0) のはず） |
| `(expt 0.5 -4294967296)` | division-by-zero（結果は floating-point-overflow のはず） |
| `(expt 1d-300 -2000)` | division-by-zero（結果は floating-point-overflow のはず） |

即座に正しく返るもの: `(expt #c(0 1) 4294967296)` => 1、`(expt #c(0 1) 4294967297)` => #C(0 1)、`(expt -1.0 4294967297)` => -1.0、`(expt 2.0 4294967296)` と `(expt #c(1.0 1.0) 4294967296)` は floating-point-overflow（CL のとおり）、`(expt 1.0000001d0 4294967296)` => 3.373264787490747d186、指数が bignum `(ash 1 70)` の整数・分数・浮動小数の底も即答。

## 期待
- 有理複素数の底: ±i と同じ単位の場合を除き、結果が表せないほど大きいなら power-number-too-large で即座に失敗する。
- 浮動小数の底の負の指数: 正の指数の結果があふれるときは、逆数の累乗（0.0 に潰れるか、あふれる）として計算する。
