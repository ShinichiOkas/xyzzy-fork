# BUG-0058 印刷のプロポーショナルフォントで、DEL（^?）の幅が「^」＋「_」で計算される

- 状態: 未修正（2026-11-22、S4 段 3 R3 で見つけた。R3 は元の動きを保つために同じ式を残した）
- 対象: src/print.cc の `print_engine::init_font`（0.2.2.235 の取り込みの時点から）

## 症状
- 固定ピッチでないフォントで印刷するとき、`init_font` は ASCII の各文字の幅を前もって計算する。制御文字は「`^` の幅 + `@` を足した文字の幅」、DEL は「`^` の幅 + `?` を足した文字の幅」のつもりで書かれている。
- DEL の行は `get_glyph_width ('?' + i, ...)` で、`i` は直前の `for (i = 0; i < ' '; i++)` を抜けた後の値（`' '`）。このため、実際に引くのは `'?' + ' '`（0x5f = `_`）の幅になる。`^?` と描く DEL の送り幅が `_` の幅に引きずられる。

## 読み取った意図
- DEL の表示は `^` と `?` の 2 文字（paint_line）。幅も `get_glyph_width ('^') + get_glyph_width ('?')` が意図と読める。

## 参照箇所
- src/print.cc の `print_engine::init_font`（`pe_glyph_width.cache (CC_DEL, ...)` の行）
