# BUG-0043 FontSet::create の「全角が半角の 2 倍でない」判定が、幅が 0 でなければ常に真になる

- 状態: 修正済み（2026-11-22）
- 対象: x64 版（feature/x64-only、59f7cfe）。x64 固有ではない（0.2.2.235 の取り込みの時点から）
- 起票: 2026-11-22（S4-c の設計の調査 docs/refactoring/s4-char-design.md §12 で見つけた）

## 症状
- src/font.cc の `FontSet::create` の末尾で、各フォントに「文字ごとの送り幅の指定（パディング）が要る」かを決める条件が `fs_font[i].size ().cx != fs_size.cx || ex[i][0].cx * 2 != ex[i][0].cx` になっている。後ろの項は `x * 2 != x` で、`x` が 0 でなければ常に真。そのため、フォントの大きさが同じでも常にパディングが要る（`fs_need_pad = 1`）ことになり、パディングを省く経路（src/disp.cc の `need_pad_p ()` が偽のとき）が使われない。

## 読み取った意図
- `ex[i][0]`・`ex[i][1]` は `FontObject::get_metrics` が返す、半角の "A" と全角の "あ" の幅（GetTextExtentPoint32）。したがって意図は「全角の幅が半角の 2 倍にならないフォントはパディングが要る」で、`ex[i][0].cx * 2 != ex[i][1].cx` と読める。添字の打ち間違い。

## 修正
- 条件を `ex[i][0].cx * 2 != ex[i][1].cx` にした。

## 表示の確かめ（2026-11-22、撮影）
- 修正すると、パディングを省く経路が使われる設定が出る（表示が変わりうる）ので、直す前後の本体で同じ画面を撮って突き合わせた。窓を PrintWindow で画像にし、テキスト領域の画素を比べた。画面には、ASCII・数字・半角カナ・全角・全角空白・タブ・コメント・字下げの入った Lisp を並べた。
- 設定（ASCII／日本語／大きさ）: FixedSys／ＭＳ ゴシック／11（既定）、ＭＳ ゴシック／ＭＳ ゴシック／12、Consolas／ＭＳ ゴシック／12、Arial／ＭＳ ゴシック／12、Courier New／ＭＳ ゴシック／12、FixedSys／ＭＳ ゴシック／10 と 12、全言語をＭＳ ゴシック 12 と 9、全言語を FixedSys 10。
- 結果: すべての設定で、テキスト領域は修正の前後で画素が一致した（差はカーソルの点滅の列だけ）。表示は変わらない。
- 限界: 修正で `need_pad_p ()` が偽になった設定があったかは、本体の外から観測していない。偽になっても上の設定では見た目が同じ、ということまで確かめた。
