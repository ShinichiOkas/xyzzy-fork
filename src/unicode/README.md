# src/unicode: mapping tables

These are the mapping tables from which the conversion tables of the codec
layer (`src/codec*.cc`, generated by `src/gen-codec.cc` into
`src/gen/codec-tab.cc`) and the old tables (`src/gen-ucs2tab.cc`) are built.
The build reads only these files; it does not use the code pages of the OS.

## Files added for the codec layer

| file | what | origin |
|---|---|---|
| CP932.TXT | cp932 (Windows-31J) to Unicode. Header of the file: "cp932 to Unicode table", Unicode version 2.0, table version 2.01, date 04/15/98, contact Shawn.Steele@microsoft.com | https://www.unicode.org/Public/MAPPINGS/VENDORS/MICSFT/WINDOWS/CP932.TXT, taken on 2026-11-22 |
| ibmext-sjis-eucjp.txt | the 388 IBM extension characters of Shift_JIS (FA40-FC4B) with their EUC-JP codes | The pairs that `gen-ibmext.cc` has had in its source. The comment there names the OSF Japan Vendor Council table, http://www.opengroup.or.jp/jvc/cde/ibmext-table.html. This file only moves them to a table |

CP932.TXT carries no condition of use in the file itself. The Unicode
Consortium's page https://www.unicode.org/copyright.html (read on 2026-11-22)
says that its Terms of Use cover the data files under
https://www.unicode.org/Public/, and the file is under that path. Check that
page before redistributing the file outside this repository.

## The other files

8859-*.TXT, CP125x.TXT, KOI8-*.TXT, BIG5.TXT, GB2312.TXT, KSC5601.TXT,
JIS0212.TXT, CNS11643.TXT and eucJP-ibmext.txt came with the first import of
the sources (commit 99909b1). The origin and the terms of each file are in
its own header.

## What gen-codec.cc adds to CP932.TXT

CP932.TXT is a table for reading (code to Unicode). It does not tell which
code to write for a character that has more than one code, and it does not
have these:

- The user defined area F040-F9FC is U+E000-U+E757.
- The single byte 0x80 is U+0080. 0xA0 and 0xFD-0xFF are undefined (a byte
  that no character corresponds to).
- Writing: a Unicode that has more than one code takes the code of the
  first of these classes: JIS X 0208, NEC row 13 (87xx), IBM extension
  (FA-FC), NEC selected IBM extension (ED, EE). This is the code that
  `WideCharToMultiByte(932)` of Windows takes. `unittest/codec-tests.l`
  checks all the codes against the OS of the machine that runs the test.

## What gen-codec.cc adds to BIG5.TXT

BIG5.TXT has "no mapping" (U+FFFD) at 5 codes where Big5 has a copy of
another character. They are given the character of the other code
(A15A=A1C4, A1FE=A2AC, A240=A2AD, A2CC=A451, A2CE=A4CA) for reading and are
never written. A1C3 is U+FFE3 and A1C5 is U+02CD. This is what the table of
`gen-ucs2tab.cc` has done.
